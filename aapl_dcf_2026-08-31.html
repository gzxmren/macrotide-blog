骨架先定：五年还是十年

换一个新标的时，第一步不是填假设，是定模型骨架——显式期几年，决定了表有几列、终值怎么接、敏感性表长什么样。填完再改等于返工。

这个判断有两条机械判据：终值占企业价值超过 85%，说明前几年的预测根本没在干活；末年资本开支比稳态所需高出 5 个百分点以上，说明缺一段过渡期，价值是靠终值补丁撑着的。任一条触发就得拉长到十年。

我此前做的两个模型给出了完全相反的答案，原因也完全不同。微软的资本开支占收入 46.5%，而稳态只需要约 27%，中间 20 个百分点的落差必须用过渡期消化，所以要十年；英伟达是无晶圆厂模式，资本开支只占收入 2.8%，根本没有落差，五年就够。

苹果跑出来是这样：

人工判断我是怎么做的

不靠感觉裁决。我把"五年够用"这个判断推成一个可以证伪的预测：如果它成立，那么把显式期延长到十年，每股价值就不该有显著变化。这个推论可以直接去验。

预测被证实，骨架选择不改变结论，所以定五年——少编五年数字。而且乐观档那 1.79% 的来源也查清楚了：只有它的末年增速还没收敛到永续增长率。

一条要说清楚的话 第二条判据用的是绝对百分点，而这个阈值当初是按微软那种 46% 资本开支强度的工况定的。苹果的资本开支只有 2%–3%，绝对差天然到不了 5 个百分点——三档的相对差其实是 +9.4% / +12.1% / +16.1%，并不算小。对低资本开支的公司，第二条判据是"必然通过"的，那个对勾不携带信息。结论只能靠第一条判据加上面那个延长期实验独立支撑。同样的问题在英伟达上已经出现过一次，这次是复现。

三处会改结论的口径

基本面数据我一律取 SEC 的 XBRL 接口。做英伟达那次踩过教训：yfinance 有三处错——股数给的是基本股数而不是稀释股数，固定资产净值高了 28%（因为混进了经营租赁使用权资产），应收账款字段差了 30 倍。从那以后这个项目不再用它取基本面。

其一：折旧口径，这次差 46%

现金流量表里的"折旧与摊销"和固定资产附注里的"折旧"是两个数。微软和英伟达上我都在这里栽过，各差 18.5%。苹果的缺口最大：

Depreciation（纯固定资产折旧，正确口径）$8,000M
DepreciationDepletionAndAmortization（含摊销）$11,698M
差异+46%

英伟达那次的教训是：只核对反推出来的折损年限这一个结果，会得出"没问题"的结论——当时分子分母同时错，结果只差 0.02 年。所以这次我用了一条独立的检验，固定资产滚动表：

期初 45,680 + 资本开支 12,715 − 折旧 8,000= 50,395
期初 45,680 + 资本开支 12,715 − 折旧摊销 11,698= 46,697
实际期末固定资产净值49,834

用纯折旧算差 1.1%（差额是处置），用折旧摊销算低了 6.3%。滚动表把口径选择独立判死了——这不是同一个事实换个写法数两遍，它是一条能失败的检验。据此反推的折损年限是 6.50 年。

其二：稀释股数，取哪个时点差 2.3%

苹果每年回购约 2.6% 的股本，这让"用哪个时点的股数"从细节变成了一个真问题。

其三：营运资本的符号我确定不了，所以取 0

苹果的营运资本长期为负——应付账款一直大于应收加存货，等于占用上游供应商的资金。但模型需要的不是水平值，是边际率：每多一块钱收入，占用多少营运资本。这个数的符号不稳定。

单年读数在正负 19% 之间摆，因为分母有时极小——FY2024 的收入只增长了 77.5 亿。换一个口径更麻烦：从现金流量表倒推的营运资本变动是收入的 −1.42% / +0.36% / −2.88% / −0.23% / −6.05%（FY2021 至 FY2025），量级大得多，但这个残差里混进了没有单独披露的递延所得税，不能直接采信。

证据不足以断定方向，所以这一项取 0，并在敏感性表里给出正负 5% 的带宽。全带宽对估值只有正负 0.6% 的影响。

这是"不知道就说不知道"，不是漏填。把它估到小数点后两位是浪费力气——真正的杠杆在贝塔系数和股权风险溢价上，各能动 10%–13%。

反推：现价要什么才成立

比"模型说它值多少"更有用的问法是：保持其余假设不变，某一条假设要变成多少，模型才等于 319.70？每一条都必须配一个硬参照——参照系只能是这家公司自己的历史实际值，或者算术上限，不能凭印象写"行业平均"。

四条路都不通。但四条都不通这件事本身，反而提示了另一种可能。

连着三次说贵，所以我查了自己的框架

微软、英伟达、现在苹果——同一套框架连续三次得出"现价越过模型天花板"。这时候该问的不是第四个标的，而是：如果这个结论是对的，它还必然意味着什么？

答案有两种。要么大型科技股确实整体贵，要么我的折现率口径有系统性的向下偏差。第二种可能必须自己查，不能等着被市场推翻。

我用的做法是把问题反过来问，绕开整个贝塔系数和风险溢价的争论：不问"按我设定的折现率它值多少"，而问"在现价买入、按各档现金流，隐含的年化回报是多少"。这个数是解出来的，不是我设的——它不依赖我选的任何一个折现率参数。

现价隐含的股权风险溢价大约是 1.36%，而本模型用的是 4.75%。

所以这不是"模型说苹果一文不值"，而是"现价把长期年化回报压到了无风险利率加 1.5 个百分点"。同一个口径对微软和英伟达同样适用——三次说贵不是我参数选择上的偶然，它就是同一句话：大型科技股现价隐含的风险溢价已经接近于零。

这句话是可以证伪的：如果未来十年苹果的年化总回报显著高于 6%，上面这个判断就被推翻了。我把它写在这里，将来不许改口。

还有一条自查：结论有没有只朝一个方向

三档全部低于市价，那会不会是我在单向地压低？判据是——如果同一条证据指向相反方向，我会照改吗？会。这一轮取数里方向本来就是混的，我全部照单采纳了：

苹果的资本开支在往下走

这是做模型时顺手撞见的一件事，和估值结论无关，但我觉得比估值结论更值得盯。

收入涨 16%，资本开支反而降 28%。资本开支占收入的比例从 FY2025 的 3.06% 掉到 FY2026 预计的 1.97%。前三季的经营现金流已经超过了 FY2025 全年。

在所有同行都在为 AI 基础设施加杠杆的时候，苹果在往相反方向走。这有两种读法，我倾向于把它当成一个待观察项而不是结论：一种是它真的更轻资产——把算力压力交给了合作方和端侧芯片；另一种是它在这一轮的投入不足，而账单会晚几年到。如果是后者，我这个模型用历史资本开支路径外推，会系统性低估它未来的资本需求。这一条我已经记进模型的缺陷登记里了。

这个模型的已知缺陷

一共登记了九条，这里挑四条说。第四条对模型是偏宽松的，不是偏保守的——只登记对自己有利的缺陷，等于没登记。

一、股权激励没有加回

模型把股权激励（FY2025 是 128.63 亿美元）当作真实成本留在营业利润里。这是有意的——它确实稀释股东。但代价是：本模型算出的自由现金流会系统性低于"经营现金流减资本开支"这个常见口径，差额大约就是一个股权激励的量级。看到别处引用的苹果自由现金流数字比我这里高，多半是这个原因，两种口径不能混着比。

二、折损年限在漂

反推出来的隐含折损年限八年里单调上行：4.12 → 4.23 → 4.45 → 5.15 → 5.60 → 5.91 → 6.50。用 FY2025 的 6.50 去预测 FY2024 的折旧，会偏低 9.1%。对估值影响很小（把年限从 6.50 改到 8.00 也只动 +0.3%），但这个趋势本身值得盯——它意味着资产结构在往长寿命的方向变。

三、监管风险没有进参数

谷歌为默认搜索位置支付给苹果的费用，量级在每年两百亿美元上下，而且几乎是纯利润。如果反垄断救济措施让它中断，会直接冲击利润率假设。我没有把它写进任何一档情景——因为我无法可靠地量化它中断的概率和幅度，硬填一个数字只会制造精确的假象。它只作为缺陷登记。

四、终值的再投资假设偏宽松

中性档终值隐含的投入资本回报率是 240%——也就是说，模型假设苹果只要把 1.25% 的税后经营利润再投进去，就能永远保持 3% 的增长。对苹果来说这不算离谱（它的投入资本本来就极少），但必须说清楚：这一维度上模型是站在乐观一侧的。

如果换成更常规的假设把终值投入资本回报率压到 30%，再投资率就要从 1.25% 提到 10%，中性档大约会从 151.82 掉到 142 附近。

方法是可以复核的

这个模型不是一次性测算，它是一套会长期维护的工作簿——每次财报后按同一口径更新，观察价值假设怎么变，而不是股价怎么变。为了让它不至于悄悄坏掉，写盘之后有四步校验：把基期输入读回来对脚本、用读回来的输入重算再对表内快照、核对表结构、最后求值表里的 Excel 公式链去对 Python 引擎。

最后那一步是后来补的，起因是我发现前三步有一个共同的盲区：它们只把假设读回来喂给 Python 引擎，从来没有碰过表里的公式。公式写错、引用错行，前三步照样全绿。我做过一次验证：把某一年折旧公式里的折损年限误引成税率，前三步全部通过，只有第四步报出 2.77 美元的偏差。

这类"看起来在保护、实际没接上"的护栏，我在这个项目里已经攒到第九例了。判据只有一个：如果它现在就是坏的，我看到的会有什么不同？答不出差别，那个对勾就不携带信息。

如果你觉得我哪一条读反了，欢迎直接说。财务数字我都对过 SEC 的原始申报，但 FY2026 第四季度还没有申报，那部分是我用三种方法各估了一次取中位数，带宽正负 0.46%——这一段是估计值，不是实际值。
